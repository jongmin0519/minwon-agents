## 📋 프로젝트 개요

지자체 민원의 **접수 → 분석 → 배정 → 처리 → 완료** 전 과정을 하나의 흐름으로 연결한 민원 관리(ITSM) 플랫폼입니다.
규칙 기반 AI 판정과 생성형 AI 답변 추천을 결합해, 민원 분류·부서 배정·중요도 산정·해결방안 도출을 자동화했습니다.

### 서비스 흐름

```
민원 등록 → AI(민트) 분석 및 부서 추천 → 관리자 검토(승인/보류)
→ AI(민지) 해결방안 추천 → 담당자 처리 및 완료
```

## 🙋 담당 역할

본 프로젝트에서 저는 **데이터 담당**을 맡아 아래 세 영역을 수행했습니다.

### 1. 데이터베이스 설계 총괄

전체 데이터 모델의 기본 틀을 설계했습니다.

- `Complaint`(민원)를 중심으로 한 엔티티 관계 구조 설계
- 기준 정보를 **Static Entity**로 분리 — 민원 유형·부서·등급·SLA 정책을 코드가 아닌 데이터로 관리해, 기준이 바뀌어도 로직 수정 없이 대응 가능한 구조 확보
- `Complaint.CurrentGradeId`를 최신 `Assessment` 결과의 **캐시 속성**으로 두어, 목록 조회 시 매번 평가 이력을 조인하지 않도록 설계
- `Assessment`를 별도 엔티티로 분리해 AI 평가 이력을 누적 보관 — 관리자가 AI 판정을 보류·수정한 근거를 추적할 수 있고, 추후 에이전트 정확도 검증 데이터로 활용 가능
- N:M 관계는 Junction Entity로 구현, 외래키 삭제 규칙을 Delete Rule로 통제
- 기준정보 세팅 및 기존 민원 데이터 Import, Aggregate 구성

### 2. 민트(Mint) 에이전트 주도 개발

3개 에이전트 중 **민트를 주도적으로 설계·구현**했습니다.

**아키텍처 결정 — "AI는 판단, 로직은 연산"**

에이전트 설계 초기에 제가 제안해 팀 전체 원칙으로 채택된 구조입니다.

| 구분 | 담당 | 내용 |
|---|---|---|
| **판단** | AI (민트) | 민원 유형 분류, 담당부서 추천, 긴급도·영향도 채점, 악성 여부 판별 |
| **연산** | 서버 로직 | 중요도 점수 합산, 등급 산정, SLA(처리기한·경고일) 계산 |

같은 민원에 대해 매번 다른 처리기한이 나오면 행정 시스템으로 쓸 수 없다고 판단했습니다. 등급과 SLA는 결정론적으로 계산되어야 하는 값이므로 AI에 맡기지 않고 서버 액션으로 분리했고, AI는 정성적 판단만 담당하게 했습니다. 결과적으로 AI 응답이 흔들려도 **처리기한 계산은 항상 동일**합니다.

**분류 방식 결정 — 벡터 검색 대신 규칙 매칭**

민트는 RAG가 아니라 Knowledge 문서(`Mint.Knowledge.txt`) 기반 규칙 매칭으로 구현했습니다.

민원 분류는 5개 카테고리·5개 부서라는 **닫힌 집합** 안에서의 선택이라, 벡터 스토어를 구축·유지할 만큼 복잡한 문제가 아니라고 봤습니다. 임베딩 생성과 유사도 검색을 매 민원마다 수행하면 응답 지연과 API 비용이 발생하는데, 그 대가로 얻을 정확도 향상이 크지 않다고 판단했습니다. 실제로 민트는 경량 모델 단일 호출로 처리되어, 민원 등록 직후 즉시 분류 결과를 보여줄 수 있습니다.

> 반면 민지(Minzi)는 과거 사례라는 **열린 집합**을 다루므로 RAG가 적합합니다. 두 에이전트에 서로 다른 방식을 적용한 것은 문제 성격에 따른 의도적 선택입니다.

**구현 범위**
- Knowledge 문서 설계 (카테고리·부서 매핑, 채점 기준, 악성 판별 기준, 안전 오버라이드 규칙)
- 프롬프트 설계 및 반복 튜닝
- 판정 결과를 Static Entity Id로 변환하는 서버 액션
- 등급·SLA 산정 로직

### 3. UI 개선

- 관공서 서비스에 맞는 톤으로 화면 레이아웃 개선
- 개별 화면 스타일 직접 수정 및 시각적 일관성 정리
  
### 주요 사용자

- **민원인** — 민원 신청, 처리 현황 조회
- **민원 처리 담당자** — 배정 민원 처리, AI 추천 답변 기반 회신 작성
- **관리자** — 민원 분류·배정 검토, 대시보드 모니터링, 사용자 관리

## ✨ 핵심 기능

- **AI 민원 자동 분류 및 부서 추천** — 민원 유형 5종, 담당 부서 5종 자동 판정
- **악성 민원 판별** — 민트가 악성으로 판별하면 자동 반려가 아니라 **주의 표시**로 처리됩니다. 표시된 민원은 별도 흐름으로 분리해 악성 민원끼리 모아 처리하도록 했습니다. 정당한 항의를 시스템이 임의로 차단하면 안 되므로 최종 판단은 관리자에게 남기되, 일반 민원 큐가 오염되지 않도록 동선을 분리한 구조입니다.
- 
- **중요도 등급 및 SLA 자동 산정** — 긴급도·영향도 채점 기반 4단계 등급, 등급별 처리기한 자동 계산
- **과거 사례 기반 해결방안 추천** — 벡터 검색(RAG)으로 유사 민원 사례를 찾아 답변 초안 생성
- **부서 간 협업 워룸(War Room)** — 다부서 복합 민원의 이관·논의·최종 답변 통합
- **알림 시스템** — 담당자 배정, SLA 마감 임박, 지연 위험, SLA 위반 알림
- **관리자 대시보드** — 민원 처리 현황 및 통계 조회
- **공지사항 · FAQ · 마이페이지** 등 대민 서비스 기능

## 🤖 AI 에이전트 구성

역할이 분리된 3개의 AI 에이전트로 구성됩니다.
**AI는 판단만 담당**하고, 등급 산정·SLA 계산 같은 규칙 연산은 서버 로직이 전담하도록 설계했습니다.

### 1. 민트 (Mint) — 민원 분석·악성 판별 에이전트

- **방식**: 경량 언어 모델(Gemini) + 고정 판단 기준 문서(Knowledge) 기반 규칙 매칭
- **역할**: 민원 유형 분류, 담당부서 추천, 긴급도·영향도 채점, 악성 여부 판별, 판단 사유 작성
- **기준값**

| 구분 | 값 |
|---|---|
| 민원 유형 | 고충민원 / 건의 / 단순질의 / 법령질의 / 신고 |
| 담당 부서 | 도시교통부 / 안전건설부 / 주민복지부 / 행정경제부 / 환경녹지부 |
| 중요도 등급 | 긴급 / 높음 / 보통 / 낮음 |
| SLA(처리기한) | 긴급 1일 · 높음 3일 · 보통 7일 · 낮음 14일 |


![데모](./demo.gif)

### 2. 민지 (Minzi) — 민원 처리 지원 에이전트

- **방식**: 생성형 + 검색형 융합(복합 RAG), 추론 모델 사용
- **역할**: 과거 유사 민원 사례를 벡터 검색해 근거로 삼고 답변 초안 생성 (환각 방지)
- **데이터**: 초기 충남 민원 데이터 582건 + 매일 자정 배치로 전일 종료 건 자동 벡터화 추가
- **설계 원칙**: 민트의 판정 결과(등급·부서·점수·SLA)는 참조만 하고 재계산하지 않음


![데모](./demo_minzi.gif)

### 3. 이브 (EVE) — 부서 간 협업 지원 AI 비서

- **역할**: 워룸 개설, 부서 이관, 대화 내용 요약, 시민 제출용 최종 답변 통합
- **부가 기능**: 공지사항 등록, 긴급 민원 알림 발송, 우선 처리 민원 조회, 신규 사원 등록 및 권한 부여

## 🗂️ 데이터 모델

`Complaint`(민원)를 중심으로 다음 엔티티가 연결됩니다.

- **민원 처리**: `Complaint` ─ `Assessment`(1:N, AI 평가) ─ `Reply`(1:1, 답변)
- **기준 정보(Static)**: `Category` · `Department` · `Status` · `Grade` · `RoleType` · `WarnType` · `SlaPolicy`
- **부서 협업**: `WarRoom` ─ `WarRoomParticipant` ─ `WarRoomMessage`
- **사용자·알림**: `UserExtension` · `WarnAdmin` · `WarnCitizen`

N:M 관계는 Junction Entity로 구현했으며, 외래키 삭제 규칙은 Delete Rule에 따릅니다.
