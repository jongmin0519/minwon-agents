## 📋 프로젝트 개요

민원 처리 담당자와 관리자가 수많은 민원을 일일이 읽고 **분류·배정·중요도 판단**을 수작업으로 처리하면서 발생하는 지연 문제를, **규칙 기반 AI 판정 + 생성형 AI 답변 추천**으로 해결하는 지자체 민원 관리(ITSM) 시스템입니다.

### 해결하려는 문제
- 관리자가 민원의 긴급도·영향도·담당 부서를 직접 판단해야 해 처리 시간이 길고 담당자마다 기준이 제각각
- 과거 유사 민원 처리 사례가 흩어져 있어 재활용이 어렵고, 노하우가 담당자 개인에게 갇혀 있음
- 등급별 처리기한(SLA)을 사람이 수기로 계산·추적하다 보니 마감 임박·지연 건을 놓쳐 SLA 위반 발생

### MVP 흐름
```
민원 등록 → AI(민트) 분석 및 부서 추천 → 관리자 검토(승인/보류)
→ AI(민지) 해결방안 추천 → 담당자 처리 및 완료
```

## 🤖 AI 에이전트 구성

시스템은 역할이 분리된 3개의 AI 에이전트로 구성됩니다. **AI는 판단만 담당**하고, 등급 산정·SLA 계산 같은 규칙 연산은 서버 로직이 전담하도록 설계했습니다.

### 1. 민트 (Mint) — 민원 분석·악성 판별 에이전트
- **방식**: 경량 언어 모델(Gemini) + 고정 판단 기준 문서(Knowledge, 규칙 매칭 방식)
- **역할**: 카테고리(민원 유형) 분류, 담당부서 추천, 긴급도·영향도 채점, 악성 여부 판별, 판단 사유 작성
- **분류 기준값**
  - 민원 유형(5종): 고충민원 / 건의 / 단순질의 / 법령질의 / 신고
  - 담당 부서(5종): 도시교통부 / 안전건설부 / 주민복지부 / 행정경제부 / 환경녹지부
  - 중요도 등급(4단계): 긴급 / 높음 / 보통 / 낮음
  - SLA: 긴급(1일) / 높음(3일) / 보통(7일) / 낮음(14일)

### 2. 민지 (Minzi) — 민원 처리 지원 에이전트
- **방식**: 생성형 + 검색형 융합(복합 RAG), 추론 모델 사용
- **역할**: 과거 유사 민원 사례(벡터 검색)를 근거로 답변 초안 생성, 근거 없는 환각 답변 방지
- **데이터 소스**: 초기 충남 민원 데이터 582건 + 매일 자정 배치로 전일 종료 건 자동 벡터화 추가
- **원칙**: Mint의 판정 결과(등급·부서·점수·SLA)는 참조만 하고 재계산하지 않음

### 3. 이브 (EVE) — 부서 간 협업 지원 AI 비서
- **역할**: 다부서 복합 민원 처리 시 워룸(War Room) 개설, 부서 이관, 대화 요약, 최종 답변 통합
- **부가 기능**: 공지사항 등록, 긴급 민원 알림 발송, 우선 처리 민원 조회, 관리자 명령을 통한 신규 사원 등록

## 🗂️ 데이터 모델 (ERD 핵심 엔티티)

`Complaint`(민원)를 중심으로 `Assessment`(1:N, AI 평가), `Reply`(1:1, 답변), `Category`/`Department`/`Status`/`Grade`(기준 정보), `WarRoom`/`WarRoomParticipant`/`WarRoomMessage`(부서 협업), `UserExtension`/`RoleType`(사용자·권한) 등으로 구성됩니다.
